# Partner cards: source, ordering and validation

The source is **`scripts/partners.json`**. The three HTML partner grids are generated by `scripts/build-partners.py`, also called by `scripts/build-site.py`. Everything outside the grids remains owned by the existing HTML files.

## Add a partner

1. Add one entry to `scripts/partners.json` with a unique `id` and a unique integer `priority` greater than the current maximum. Higher priority appears first. These are ordering values, not historical dates. Keep existing priorities unchanged to retain their relative order.
2. Supply the official HTTPS URL and all three localized `content` objects: title, existing-style image markup, description paragraphs and partner badge. HTML fields are trusted repository content; do not insert unverified markup. Keep the full-card anchor convention and do not nest links inside it. Contacts are displayed as text, matching the existing cards.
3. Store verified logo assets in `img/partnerzy/`, with accurate dimensions, localized ALT and responsive derivatives where appropriate.
4. Run `python3 scripts/build-site.py`, then `python3 scripts/check-partners.py` and `git diff --check`. The build refreshes Markdown/AI resources.
5. Run `scripts/check-partners.cjs` with Playwright and a local HTTP server. Default base URL: `http://127.0.0.1:8794`; override with `LTS_TEST_BASE`.

`python3 scripts/build-partners.py --check` is read-only and fails if a generated grid is stale. The scoped validator includes an in-memory priority mutation check and verifies that check mode does not write files. Update its expected ID order when intentionally adding another partner.
