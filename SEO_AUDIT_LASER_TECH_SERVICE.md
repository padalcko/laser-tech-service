## Інвентаризація та результати перевірок

### Сторінки, метадані й локалізація

- Перевірено canonical, hreflang, `x-default`, `meta robots`, Open Graph, H1, JSON-LD і sitemap для всіх 246 опублікованих URL.
- Кожна сторінка має власний canonical URL; canonical узгоджується з `og:url`.
- Знайдено 246 унікальних title і 246 унікальних meta description; на кожній перевіреній сторінці один H1.
- Hreflang-пари взаємні, містять self-reference та відповідають мовним URL у sitemap. Винятки з кодами `pl-PL`/`ru-RU` стосуються двох мовних груп і застосовані послідовно; інші сторінки використовують `pl`, `ru` та `en`.
- `x-default` присутній у групах мовних альтернатив. Три заплановані EN-маршрути не включені до sitemap і на них немає посилань з опублікованого англомовного контенту.
- `robots.txt` дозволяє сканування сторінок і містить адресу sitemap. Сторінка 404 має `noindex, follow` і не входить у sitemap.
- Перевірено 532 JSON-LD блоки на коректний JSON і узгодженість основних типів схеми з видимим вмістом. FAQPage використовується там, де є відповідний видимий FAQ; її відсутність на інших сторінках не є помилкою.
- Open Graph URL узгоджений з canonical; title/description присутні та не дублюються між сторінками.
- Точних дублікатів основного вмісту в межах мов не виявлено.

### Посилання, sitemap і HTTP

- Перевірено 33 440 внутрішніх посилань і фрагментів: битих внутрішніх цілей, неіснуючих фрагментів, внутрішніх посилань на redirect або orphan-сторінок не знайдено.
- У production усі 246 URL sitemap повернули HTTP 200.
- Усі 51 перевірене правило перенаправлення повернули очікуваний HTTP 301 без redirect-ланцюжків. HTTP і `www` приводяться до основного HTTPS-хоста.
- Перевірений неіснуючий URL повертає HTTP 404.
- Перевірено 469 URL локальних зображень і CSS на production; усі повернули HTTP 200.
- Публічний обхід не виявив сторінок, які є в sitemap, але не доступні напряму.

### Посадкові сторінки послуг, блогу та Realizacje

- Інвентаризація та локальні валідатори охопили всі 246 опублікованих сторінок усіх трьох мов, зокрема сторінки послуг, статті блогу та Realizacje.
- Перевірено унікальність метаданих, мовні альтернативи, внутрішні посилання, наявність H1, основну структуру сторінок і відповідність JSON-LD видимому вмісту.
- Перевірки англомовних сторінок підтверджують 16 сторінок послуг із відповідними даними каталогу; заплановані, ще не опубліковані маршрути не просочуються в навігацію чи sitemap.
- Не виявлено точних дублікатів основного вмісту в межах однієї мови. Повна редакційна оцінка корисності, оригінальності, перекладів і фактичної точності потребує людського контент-рев'ю та виходить за межі машинної технічної перевірки.

### Зображення, CSS, JavaScript і Core Web Vitals

- У HTML перевірено 3 572 зображення: порожніх або відсутніх `alt` не знайдено.
- Під час повторної інвентаризації знайдено 2 470 зображень без одночасних `width` і `height`. Це були 10 повторюваних SVG-іконок меню/футера на кожному HTML-файлі, а не фотографії. Додано intrinsic dimensions із самих SVG; тепер у всіх 3 572 зображень задані обидва розміри.
- Після оновлення генератора 652 зображення мають `srcset` і `sizes`; немає випадків `sizes` без `srcset`, а всі локальні файли з `srcset` існують. Шість карток послуг отримали варіанти, що вже були на диску; у трьох карток без responsive-файлів прибрано недійсний `sizes`. Не змінювалися фотографії, CSS-розміри чи співвідношення сторін.
- Інвентаризація охопила 475 raster-файлів загальним розміром 55 583 261 байт. У каталозі зображень переважає WebP; найбільший перевірений WebP має приблизно 506 KB.
- Окремий пошук зображень повідомив 78 збігів у `docs/`, `reports/` і `scripts/`. Ручна перевірка прикладів показала, що це назви файлів у текстових інвентаризаціях/звітах і тестових рядках, а не URL зображень у публічних HTML/CSS/JS. Публічних битих посилань на зображення не знайдено. Через ці текстові збіги `scripts/audit-images.py` завершується ненульовим кодом — це обмеження його широкого пошуку, а не підтверджена помилка сайту.
- Попередні одиничні виміри без контрольованого throttling, наведені в попередній версії аудиту, не є польовими Core Web Vitals. Контрольовані повторні мобільні вимірювання та фактичні LCP-елементи наведено в розділі продовження нижче.
- Перевірки не виявили локальних битих посилань на CSS/JS. Повне виконання окремих JavaScript/browser-тестів обмежене відсутністю Node.js у середовищі.

Для решти оптимізацій потрібні польові дані та/або окреме погодження; авторські тексти й дизайн не змінювалися.

### Контрольовані мобільні вимірювання CWV

Лабораторні повтори виконано при viewport **390 × 844**, CPU throttling **×4**, RTT **150 ms**, download **1,6 Мбіт/с**, upload **0,75 Мбіт/с**, cache disabled. Наведені значення — медіани двох запусків на кожному типі сторінки:

| Тип сторінки | LCP | CLS | Фактичний LCP-елемент |
|---|---:|---:|---|
| Головна | 1,25 с | 0,010 | Фонове зображення у `HEADER` |
| Послуга | 3,46 с | 0,017 | Те саме фонове зображення у `HEADER` |
| Стаття блогу | 0,888 с | 0,031 | Текстовий `P.article-lead` |
| Реалізація | 2,192 с | 0,112 | Hero-фото `IMG` |

Локальний контрольований A/B тест дав для сторінки послуги LCP **4,41–4,61 с без preload** проти **1,65–1,80 с із preload**. Для hero-фото реалізації LCP становив **1,96–2,47 с без high priority** проти **1,56–1,60 с із ним**. Це результати локального лабораторного тесту, а не вимірювання production або польових Core Web Vitals. INP і реальний розподіл досвіду користувачів без CrUX/Search Console не встановлені. Google Ads, Analytics і Лазаря не відключали.

### Production-заголовки `noindex`

Перевірка production підтвердила, що `_headers` застосовується: наявний `/docs/lubin-report.md` повертає `X-Robots-Tag: noindex`. Однак **сім нових URL досі віддають HTTP 200 без цього заголовка**, отже зміна в робочому дереві ще не розгорнута:

- `/reports/b2b-service-report.md`
- `/reports/sapphire-service-report.md`
- `/reports/gliwice-service-report.md`
- `/reports/lightsheer-desire-wroclaw-report.md`
- `/reports/nubway-vacuum-valve-report.md`
- `/content/nubway-vacuum-valve-routes.json`

У зв'язку з вимогою не виконувати deploy це production-ризик, що залишається відкритим до розгортання та повторної перевірки HTTP-заголовків.

## Що залишилося поза можливістю перевірки

- Без Google Search Console не можна підтвердити фактичну індексацію кожної URL, canonical, вибраний Google, причини виключення сторінок, покази/кліки, ручні санкції чи звіти про rich results.
- Без CrUX/PageSpeed field data та доступу до Search Console не можна підтвердити польові LCP, INP і CLS для реальних користувачів.
- Production HTTP-заголовки перевірено для згаданих URL, але немає доступу до конфігурації/логів сервера або права deploy. На цей момент сім службових URL усе ще потребують deploy правила `noindex` і подальшої перевірки.
- Не перевірялися логи Googlebot, серверні помилки, поведінка CDN у всіх регіонах і приватні дані Google Ads/Analytics. Налаштування цих сервісів не змінювалися.
